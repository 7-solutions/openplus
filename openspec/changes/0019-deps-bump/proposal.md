# Change 0019 — Mass-bump dependencies (PLAN)

## Why
The locked dependency set is older than the available upstream. Twenty modules
have a newer release (`go list -m -u all`) — `ncruces/go-sqlite3` is the only
direct dep with a bump available (v0.20.3 → v0.35.2, 15 minor versions of
cgo-free / WASM-backed sqlite). The rest are transitive, but `go mod tidy`
will refresh them.

The AGENTS.md hard rule "Latest-stable, lockfile-pinned. Bump only after green
tests" specifically endorses periodic bumps when the suite is green. The
project has been green for the last several changes (0006, 0018, post-0018
modernization, /swe-loop skill), so this is the right moment to pull.

## What changes
- `go.mod` — direct dep `ncruces/go-sqlite3` v0.20.3 → latest (probably v0.35.2).
  Other direct deps already at latest, no changes to those.
- `go.sum` — regenerated by `go mod tidy`.
- Possible small Go code adjustments if any bumped module's API moved.
  Most likely candidates: `mattn/go-runewidth`, `charmbracelet/{bubbletea,
  bubbles, lipgloss}` indirect churn, `dlclark/regexp2`. If anything breaks,
  fix forward in the same change.

## Governing decisions
- AGENTS.md hard rule "Latest-stable, lockfile-pinned" (bump encouragement).
- AGENTS.md hard rule "Bump only after green tests" (gating).
- AGENTS.md "Pure Go / cgo-free" (must remain green after the bump, especially
  the `ncruces/go-sqlite3` jump — the entire reason that dep is in use is the
  WASM-based cgo-free story).

## Risks
- **ncruces/go-sqlite3 v0.20.3 → v0.35.2** is the biggest jump (15 minor
  versions). Risk: SQLite-version drift, sqlite-vec ABI compatibility, RRF
  fusion SQL may need adjustment. Mitigation: bake-test with the existing
  `internal/memory` golden tests; if they fail, the v0.20.3 ground-truth has
  to be revisited. If the bump is unworkable, scope cut and ship a smaller
  bump in change 0020.
- **Transitive bumps could break the lockfile symmetry** for downstream
  packagers. Mitigation: `go mod tidy` enforces the canonical graph.
- **API drift in charmbracelet or goja ecosystem** could break the TUI /
  runtime. Mitigation: `go test ./...` + smoke run of the fake-provider loop.
